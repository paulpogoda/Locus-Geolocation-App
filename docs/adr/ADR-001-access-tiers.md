# ADR-001: Две модели доступа к Gemini — BYOK (Free) и серверный ключ «Проверено» (Pro)

**Статус:** Предложено
**Дата:** 2026-10-08
**Состояние кода на момент записи:** `main` @ `1a2487d`
**Последнее обновление:** 2026-10-08, `main` @ `cfe6048`

> Публичная сокращённая версия. Полная версия с распределением задач и открытыми вопросами хранится во внутренних документах проекта.

## Контекст

LOCUS — веб-приложение для геолокации изображений (React + Vite). Анализ выполняет Gemini API с grounding через Google Search и Google Maps. Изначально приложение было экспортом из Google AI Studio.

Как менялся доступ к модели:

- **До `1a2487d`.** Ключ `GEMINI_API_KEY` встраивался в клиентский бандл через `define` в `vite.config.ts`. Любой посетитель мог его извлечь, поэтому публиковать приложение в таком виде было нельзя.
- **В `1a2487d`.** Сделан BYOK: пользователь вводит свой ключ, ключ хранится в `localStorage`, запросы идут из браузера напрямую в Gemini. Сервера нет.

Что влияет на решение:

1. **Устойчивость проекта.** Нужен тариф, который покрывает расходы, и возможность выдавать доступ партнёрским редакциям за счёт грантов.
2. **Опсек.** Пользователи — фактчекеры и OSINT-исследователи, изображения могут быть материалами неопубликованных расследований.
3. **Условия Gemini API** ([ai.google.dev/gemini-api/terms](https://ai.google.dev/gemini-api/terms)):
   - на бесплатном тарифе данные используются для улучшения продуктов Google, возможна ручная проверка людьми;
   - на платном тарифе данные для обучения не используются.
4. **Безопасность BYOK.** Ключ в браузере можно украсть через XSS. Поэтому поверхность атаки нужно сокращать:
   - не вставлять HTML из API в DOM приложения;
   - не грузить скрипты и стили со сторонних CDN;
   - задать CSP.
5. **Ресурсы.** Команда небольшая, поэтому расходы на пользователя и запрос нужно ограничить сразу.

## Решение

Поддерживаем два режима доступа в одной кодовой базе. Режимы различаются слоем провайдера (`GeoProvider`).

| | **Free (BYOK)** | **Pro (ключ «Проверено»)** |
|---|---|---|
| Путь запроса | браузер → Gemini API напрямую | браузер → бэкенд `/api` → Gemini API |
| Ключ | ключ пользователя, хранится в браузере | ключ «Проверено» в Secret Manager, платный тариф |
| Изображения проходят через «Проверено» | нет | да, без сохранения |
| Авторизация | не нужна | обязательна |
| Учёт и лимиты | на стороне Google, по ключу пользователя | квоты на пользователя, бюджетные алерты |
| Доступ | открытый | подписка или грантовый доступ для партнёров |

Принципы:

- **BYOK остаётся прямым запросом в Gemini, без нашего прокси.** «Проверено» не видит материалы бесплатных пользователей.
- **Общий код.** Промпт, схема ответа (zod), нормализация `groundingMetadata` и UI — одни для обоих режимов. Различается только транспорт.
- **Грантовый доступ — это Pro.** Технически это тот же Pro, только оплата идёт от донора. Отдельной ветки кода нет.

## Рассмотренные варианты

### Вариант A: только BYOK

**Плюсы:** быстрый запуск, нет инфраструктуры, мы не видим данные пользователей.
**Минусы:**
- нет модели устойчивости;
- порог входа: нужно завести ключ в Google;
- у пользователей бесплатных ключей нет гарантий по данным;
- ключ уязвим к XSS.

### Вариант B: только серверный ключ

**Плюсы:** единый пользовательский опыт, гарантии платного тарифа, полный контроль.
**Минусы:**
- без оплаты продукт недоступен;
- все расходы и злоупотребления на нас;
- через нас проходят все изображения.

### Вариант C: гибрид — BYOK Free + серверный Pro (выбран)

**Плюсы:**
- бесплатный доступ без расходов для нас;
- Pro даёт гарантии по данным;
- грантовый доступ для индустрии;
- бесплатные пользователи остаются вне нашего контура данных.

**Минусы:**
- два транспорта — больше тестов;
- нужна чёткая разница в ценности между Free и Pro.

## Компромиссы

- **Сложность.** Бэкенд всё равно понадобится для платного или грантового доступа. Если сделать абстракцию провайдера сейчас, не придётся переписывать всё позже.
- **Опсек.** Пользователь сам выбирает, кому доверять изображения: напрямую Google по своим условиям или «Проверено» под платный тариф Google. Это нужно прямо объяснить в интерфейсе.

## Последствия

**Станет проще:**
- запуск бесплатной версии без инфраструктуры;
- переключать модели и провайдеров через единый слой.

**Станет сложнее:**
- эксплуатация бэкенда: авторизация, мониторинг, инциденты;
- обязательства по защите данных в Pro;
- тестирование двух транспортов.

**Что пересмотреть позже:** переход на Vertex AI, если понадобятся региональное размещение данных или корпоративный SLA.
